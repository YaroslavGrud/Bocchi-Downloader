# Политика безопасности Bocchi Downloader

Спасибо, что помогаете сделать Bocchi Downloader безопаснее! Мы серьезно относимся к любым уязвимостям и стремимся оперативно их исправлять.

## 📦 Область действия политики

Данная политика безопасности распространяется на **все файлы и зависимости**, находящиеся в этом репозитории. Это включает, но не ограничивается:

*   Исходный код Python (`.py`).
*   Файлы конфигурации (`.json`, `.yaml`, `.env.example`).
*   Списки зависимостей (`requirements.txt`, `pyproject.toml`, `Pipfile`).
*   Скрипты автоматизации и Docker-файлы.
*   Любые бинарные файлы или ресурсы, входящие в состав релизов.

Если уязвимость обнаружена в **сторонней зависимости** (библиотеке, указанной в `requirements.txt`), мы будем признательны за сообщение о ней. Даже если мы не можем исправить саму библиотеку, мы можем обновить версию зависимости или применить обходное решение (workaround) в коде проекта.

## 📋 Поддерживаемые версии

Обновления безопасности выпускаются только для следующих версий проекта:

| Версия | Поддержка обновлениями |
| :--- | :---: |
| `main` (ветка разработки) | ✅ Да |
| Последний релиз (Latest Release) | ✅ Да |
| Устаревшие версии (< 1.0.0) | ❌ Нет |

> **Примечание:** Если вы используете старую версию, мы настоятельно рекомендуем обновиться до последней доступной, так как исправления для старых версий не предоставляются.

## 🛡️ Как сообщить об уязвимости

**⚠️ Пожалуйста, НЕ создавайте публичные Issue для обсуждения уязвимостей.**  
Публичное раскрытие может поставить под угрозу пользователей, которые еще не установили исправление.

### Инструкция по отправке отчета

Для сообщения об уязвимости используйте **исключительно** встроенный механизм приватного информирования GitHub:

1.  Перейдите на вкладку **Security** в верхней части этого репозитория.
2.  Выберите раздел **Advisories** (в левом меню).
3.  Нажмите зеленую кнопку **"Report a vulnerability"**.
4.  Заполните форму, подробно описав проблему и шаги для её воспроизведения.

Этот метод гарантирует, что сообщение увидят только мейнтейнеры проекта до тех пор, пока исправление не будет готово к публичному релизу.

## ⏳ Чего ожидать после отправки отчета

1.  **Подтверждение:** Мы постараемся ответить через GitHub Advisory в течение **48 часов**, подтвердив получение вашего сообщения.
2.  **Анализ:** Мы проведем оценку влияния уязвимости на проект, включая проверку зависимостей, указанных в `requirements.txt` и `pyproject.toml`.
3.  **Исправление:** Мы разработаем патч и выпустим новую версию. Если уязвимость критическая, мы можем временно откатить опасную функциональность или заблокировать проблемную зависимость.
4.  **Публичное раскрытие:** После выпуска исправления мы опубликуем Security Advisory с благодарностью вам (если вы захотите быть указанным) и техническими деталями проблемы.
